
# MJMK Website Redesign Plan

This is a large, multi-phase rebuild. I'll restructure the site into separate pages, add a full member management system with admin approval, digital ID cards, and QR verification — while preserving existing tables (`registrations`, `complaints`, `party_registrations`) so nothing currently working breaks.

## 1. Information Architecture (New Routes)

```
/                    Home (slimmed down, no overcrowding)
/leadership          Leadership & Organization (moves member cards off home)
/activities          Activities & Achievements (with animated counters)
/gallery             Gallery & Media (photos + YouTube)
/register            Member Registration (new full form)
/member/:number      Public QR verification page
/contact             Contact Us
/admin               Admin login + dashboard (existing, extended)
```

Existing routes kept: `/admin`, `/ads`, `/bearers`, `/bearers_registration`, `/party-registration`.

## 2. Database Changes (new tables only — nothing existing touched)

New table **`members`** with fields per your spec (membership_number, full_name, father_name, gender, dob, blood_group, mobile_number, whatsapp_number, email, voter_id_number, photo_url, voter_id_url, state, district, taluk, village, address, membership_type, designation, referral_name, referral_mobile, status, qr_code_url, id_card_url, approved_at, approved_by, timestamps).

- Unique constraints on `mobile_number` and `voter_id_number`.
- Status enum: Pending / Approved / Rejected / Suspended (default Pending).
- Membership number generated by Postgres sequence starting at 10030, formatted `MJMK2026{n}`.

New tables: **`user_roles`** + enum `app_role` ('admin','moderator','user') and `has_role()` security-definer function (required for safe admin checks).

RLS:
- Public can INSERT into `members` (status forced to Pending via trigger).
- Public can SELECT only `status='Approved'` rows and only a safe subset of columns (via view `public_members`).
- Admins (via `has_role`) can SELECT/UPDATE/DELETE all members.

New storage buckets (private): `member-photos`, `member-voter-ids`, `member-id-cards`, `member-qr`. Signed URLs used in admin and ID card rendering.

## 3. Admin Authentication

- Enable email/password auth.
- First admin seeded by user signing up, then promoted via SQL (one-time).
- `/admin` becomes a protected route guarded by `has_role(auth.uid(),'admin')`.
- Existing `/admin` page keeps its registrations + complaints tabs and gains a **Members** tab.

## 4. Member Registration Flow

`/register` page — multi-section form (Personal, Identity, Location, Party Info, Declaration) with Zod validation:
- Passport photo upload → `member-photos`
- Voter ID upload → `member-voter-ids`
- Mobile + Voter ID uniqueness enforced DB-side
- Submits with status=Pending, no membership number yet

## 5. Admin Approval → ID Card + QR

Edge function **`approve-member`** (admin-only, JWT validated, role-checked):
1. Assigns `membership_number` from sequence
2. Generates QR PNG (encoding `https://<site>/member/{number}`) → stores in `member-qr`
3. Renders PDF ID card (pdf-lib) with logo, photo, name, number, blood group, district, QR → stores in `member-id-cards`
4. Sets status=Approved, approved_at, approved_by
5. Returns signed URLs

WhatsApp send: opens `wa.me` link with pre-filled message from admin UI (no paid API needed unless you want Twilio later — I'll flag this).

## 6. Public Verification `/member/:number`

Reads from `public_members` view. Shows photo, name, number, district, designation, status badge "✓ Verified MJMK Member". 404 for non-approved.

## 7. Home Page Slimming

Keep: Hero (founder image, logo, slogan, Join/Volunteer/WhatsApp CTAs, Facebook + YouTube above the fold), About, Mission, Vision, Core Principles, Founder Message, Key Achievements (counter strip), Welfare highlights, Gallery preview (4 tiles → link to /gallery), Social feed embeds, Contact CTA.

Remove from home: leadership grids, full registration form, full complaint form, full gallery (moved to dedicated pages). Existing `PartyRegistrationSection` removed from home (page `/party-registration` still exists).
